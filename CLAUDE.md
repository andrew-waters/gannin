# CLAUDE.md

Gannin is a native SwiftUI macOS app (bundle ID `dev.andon.gannin`, gannin.ai) for keeping an eye on
workload across the GitHub orgs you belong to: who has which PRs, reviews and issues in flight,
and how PRs link to tickets.

Per-feature notes are in `.claude/rules/`, one file per area, and load when you open a file in that
area. Build, layout and release steps for contributors are in `README.md` and `docs/RELEASING.md`.

## Build

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from
`project.yml` and is not checked in. Regenerate after adding or removing files:

```bash
xcodegen generate
xcodebuild -project Gannin.xcodeproj -scheme Gannin -destination 'platform=macOS' build
```

To try a change in the app, `scripts/relaunch.sh` builds it signed (so it reads the same keychain
token) and, only if the build succeeds, quits every running Gannin and opens the new build, detached,
so a Claude Code session running inside Gannin resumes in it; `--no-build` relaunches the last build.

Unit tests (`GanninTests`, Swift Testing, hosted in the app) run with the scheme, as `ci.yml` runs
them on every pull request:

```bash
xcodebuild test -project Gannin.xcodeproj -scheme Gannin -destination 'platform=macOS' -skipPackagePluginValidation
```

## Conventions

- Swift 6 with `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`: everything is main-actor unless marked
  otherwise.
- Mac only (`platform: macOS`). AppKit is used directly, with no `#if os` branches.
  `App/Platform.swift` names the few shared styles (`checkboxToggle`, `linkButton`, `onEscape`,
  `windowSubtitle`, `Color.separatorLine`).
- The app isn't sandboxed while Claude Code sessions are prototyped: they run git, gh and claude as
  the user, which a sandboxed child process can't. Application Support is the shared one, not a
  container, and there are no entitlements beyond the hardened runtime.
- What the user enters (people's dates, org settings, hidden items, stars) is SwiftData on this
  device (`Sync/UserDatabase.swift`); what the team shares lives in its harnesses (see
  `.claude/rules/harness.md`). GitHub caches are local JSON in Application Support.
- A page's title is the window's and its top-level controls are toolbar items. `PinnedHeader` is
  only for section headers further down a page.
- Every write to GitHub is confirmed by the user first.

## Working rules

- A user-facing change updates its page in `docs-site/` in the same pull request: a setting added,
  renamed or removed, a new page or flow, a changed default, a new shortcut. Name things as the app
  shows them (labels, menu paths such as Settings › Sync), never by type or storage key alone.
- User-visible behaviour is documented in `docs-site/` only. This file and the rules record what
  someone changing the code needs: invariants, reasons, limits and wiring, not what a page shows.
  Pages live under `docs-site/src/content/docs/`: `guides/` (using the app), `agents/` (Claude Code
  sessions, reviews, routines), `sessions/` (where sessions run), `concepts/` and `settings/`. Each
  folder is a sidebar section in `docs-site/astro.config.mjs`, so a new folder needs an entry there.
- The Settings reference (`docs-site/src/content/docs/settings/`) has every option with its default,
  what it changes and where it's kept. `docs-site/scripts/check-settings.mjs` (the `docs` job in
  `ci.yml`) fails when a control label in a pane's Swift files, or a `SyncSource` title, isn't on
  its page; a new pane or section view goes in its `panes` map.
- A change someone using the app would notice adds a line under `## [Unreleased]` in
  `CHANGELOG.md`. Releasing is in `docs/RELEASING.md`.
- `.github/ISSUE_TEMPLATE/issue.md` asks for acceptance criteria with a Docs item, which New Issue
  and `skills/create-issue.md` follow.
- Write rules as short instructions with a reason ("Never X: Y breaks"). Add one only for a
  constraint that reading the code wouldn't reveal. Don't record how a mechanism works, constants,
  long lists of names or what a page shows. Change a rule when your change breaks what it says.
