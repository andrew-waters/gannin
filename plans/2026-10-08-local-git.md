# Local git in Gannin

## Context

Before this, Gannin's only local git work was in a Claude Code session tab's Changes pane: a
unified diff, staging whole files, discarding a file or hunk, a one-field commit and Push. Every
call was a bash script run by `SessionChanges.run`. Clone, fetch and worktree setup only happened
in a session's `start.sh` or were left to claude. The sidebar's Repositories rows showed GitHub
data alone (open PRs, issues, merged), and the landing page was delivery stats.

Audit against the issue's gap list, before this work:

| Area | Before | After stage 1 |
|---|---|---|
| 1. Clone, add, repo switcher | Missing (sessions' script only) | Present |
| 2. Branches and worktrees | Partial (session worktrees only) | Present |
| 3. Changes and diffs | Partial (file staging, hunk discard, unified diff) | Present, except split view, syntax highlighting and line staging |
| 4. Committing | Partial (one message field) | Summary, description, amend, undo |
| 5. Syncing | Partial (push, unpushed count) | Fetch, pull, push, force with lease, ahead/behind |
| 6. Tags | Missing | Present |
| 7. History | Missing | Missing (stage 2) |
| 8. Merge, rebase, conflicts | Missing | Partial: conflicts after a pull can be finished (ours, theirs, resolved, continue, abort) |
| 9. Stash | Missing | Partial: changes left on a branch when switching, restored from a banner |
| 10. PR handoff | Partial (open in editor) | Open in editor, Terminal, Finder and GitHub; PR checkout in stage 2 |

## Decisions

- **The git CLI, not a library.** Shelling out keeps the user's own config, hooks, signing and
  credential helper (`gh auth setup-git`, the keychain, ssh-agent), so Gannin never handles a git
  credential. It also works over the ssh runner sessions already use. Scripts run with
  `GIT_TERMINAL_PROMPT=0` and no stdin, so a prompt fails rather than hangs. Homebrew's folders
  are put on `PATH` before the system's.
- **One shell layer.** `Git/Shell.swift` holds the runner (moved from `SessionChanges`), and
  `Git/GitDiff.swift` holds the diff parsing and hunk patches. Sessions' Changes pane keeps its
  own views (comments for claude, a Branch mode against the base) on top of them.
- **The Repositories page, not a new one.** Repositories gains On This Mac beside its Delivery
  stats. Each repo row opens the repo's page, with Changes, Branches and Tags parts beside the
  GitHub view it already had. It moves from Delivery to Work in the sidebar, which lists the
  window's project's repos as well as those with work in flight. Local repos are on this Mac only, since a page has no session to reach a
  server through.
- **Where clones go.** The window's project's harness keeps shared clones in
  `projects/<name>`, so that's where Clone puts them. When the repo is the harness itself, the
  harness checkout is the clone. With no harness checked out on this Mac, the clone goes in
  `<workspace>/<owner>/<name>`. A clone is found by a path saved for the repo
  (`localRepository.<owner/name>`, from Add Existing or Choose), then the harness's
  `projects/`, then the usual places sessions already look in. Each candidate is checked by its
  origin.
- **Worktrees** are listed from `git worktree list`, and the page works in one at a time (the
  toolbar's worktree menu). New ones default to `<harness>/.worktrees/<branch>/<name>`, as
  Work on This lays them out, so session worktrees show up here too. A branch checked out in
  another worktree can't be switched to; the page offers to open that worktree instead.
- **Switching with changes** offers to leave them on the current branch (stashed with a
  message naming it, by its SHA, never a bare `stash pop`), to bring them along, or to cancel.
  Coming back to the branch shows a banner to restore them.
- **Hunks** are staged, unstaged and discarded with `git apply` (`--cached`, `-R`) on a patch of
  the file's header and that hunk. With whitespace ignored, the diff is for reading only, since
  its hunks wouldn't apply.
- **Pull** follows the user's `pull.rebase`. When git asks how to reconcile divergent branches,
  Gannin asks Merge or Rebase. Force push is `--force-with-lease` only, behind a confirmation.
  While a repo's page is open, it fetches in the background every five minutes. That's
  local git, not GitHub's API budget, so it isn't a Settings › Sync source.
- **Pruned from the gap list for now:** co-author trailers, line-level staging, split view and
  syntax highlighting (follow-ups), and history, stash management, branch compare and PR
  checkout (stage 2).
