# PR size in the PR and people views

## Context

Lines added and removed were already fetched for open and merged PRs and shown as one Size column
on the Pull Requests table. Files changed wasn't fetched at all, and the People page said nothing
about how big anyone's PRs are. Size over time was already tracked org-wide: `SizeStat`, the
Scorecard's PR size measurable and the PR size goal.

## Decisions

- Files changed is GitHub's `changedFiles`, a plain field on both PR queries, so it costs nothing
  extra. It's optional on `PullRequest` and `MetricPullRequest`: a snapshot cached without it is
  searched in full on the next refresh (a changes search would leave untouched PRs without it),
  and merged PRs already in the metrics history are looked up once by node ID, 100 a query (a
  point each), rather than fetching the whole history again, so the People page, goals and the
  Scorecard's past periods have file counts too.
- Lines stay one cell, `+120 -45`, sorted by lines changed (added plus removed), with Files its own
  sortable column beside it.
- People: per person, the median lines changed and median files changed per PR they merged in the
  window, as the other People columns use medians rather than means. The tooltip adds p75, total
  added and removed and how many PRs were over 400 lines. The window is the People page's metrics
  window; only merged PRs count.
- Over time: the Scorecard's PR size measurable already gives median lines changed per period,
  by team or owner, so no new history is kept.
- Generated and vendored files aren't left out: that needs every PR's file list, which costs far
  more. A possible follow-up.
